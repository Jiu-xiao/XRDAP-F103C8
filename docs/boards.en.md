# Boards

[中文](boards.md)

This document describes the two system clocks, the two flash sizes and the status light of XRDAP-F103C8; the pins are in the [README](../README.en.md). The probe is the full-speed USB device `1D50:6199` with bcdDevice `0x0400` (`xrdap/probe/family.hpp` in XRDAP-Core) and a single CMSIS-DAP v2 interface; DAP packets are 512 bytes, with 4 DAP packets (reported by DAP_Info) and a 4096-byte sampling buffer (reported by the vendor extension's INFO).

## System clock

Both firmware images set up the clocks for an 8 MHz crystal:

| Firmware | System clock | USB clock |
|---|---|---|
| `xrdap-f103c8-72m` | 8 MHz × 9 = 72 MHz | 72 MHz ÷ 1.5 = 48 MHz |
| `xrdap-f103c8-96m` | 8 MHz × 12 = 96 MHz | 96 MHz ÷ 2 = 48 MHz |

`xrdap-f103cb-72m` and `xrdap-f103cb-96m` set up the clocks as `xrdap-f103c8-72m` and `xrdap-f103c8-96m` do.

The STM32F103 runs at 72 MHz at most and its USB prescaler divides by 1 or 1.5 only, so it uses the 72 MHz firmware. The APM32F103 runs at 96 MHz and extends the USB prescaler to two bits (USBDPSC[23:22] in RCC_CFGR), which can divide by 2, so it uses either firmware. The clocks are set up in `XR_ApplyClockProfile()` in `Core/Src/main.c`.

SWD is generated by GPIO in software, with its timing calibrated in CPU cycles (`kSwdTiming` in `User/app_main.cpp`), so the SWD speed scales with the system clock.

## Flash size

`xrdap-f103c8-*` is built for 64 KB of flash, with C and C++ code at `-Os`. `xrdap-f103cb-*` is built for 128 KB of flash (CMake option `XR_FLASH_SIZE_KB=128`), with C code at `-Os` and C++ code at `-O3`; it handles DAP commands faster, its image is about 100 KB, and it needs a chip whose flash size register `0x1FFFF7E0` reads 128 KB.

The table gives the time OpenOCD 0.12.0 takes, with 0.6.0 firmware on this probe (SWD, `adapter speed 30000`), to write 128 KiB to the SRAM of an STM32H723 (`0x24000000`, `load_image`) and to read 128 KiB back (`dump_image`):

| Firmware | Write | Read |
|---|---|---|
| `xrdap-f103c8-72m` | 0.62 s | 0.62 s |
| `xrdap-f103cb-72m` | 0.48 s | 0.47 s |
| `xrdap-f103cb-96m` | 0.36 s | 0.36 s |

## Status light

Two LEDs, one red and one blue, sit in anti-parallel on PA9: PA9 high lights red, low lights blue, and as an input both are off. PA9 is the PWM output of TIM1_CH2; the duty cycle is the red share, and half red and half blue shows purple. The colours follow the status light rule shared by the XR-DAP family (the "Status light" section of the XRDAP-Core README):

| State | Light |
|---|---|
| Power-up | One sweep between red and blue, 0.8 s |
| USB not yet configured by a computer (for example on a power supply only) | Solid purple |
| USB configured by a computer, idle | Solid red |
| Debug tool connected | Red and purple back and forth, period 2 s |
| Target running | Red and blue back and forth, period 1 s |
| Every DAP command | Off for 33 ms; under steady traffic off once every 66 ms |

"Connected" and "running" are reported by the debug tool through DAP_HostStatus and cleared by DAP_Disconnect or after 5 s without any DAP command.
